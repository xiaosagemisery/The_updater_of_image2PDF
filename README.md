# 拾页 PageWeave

> 原项目名 image2PDF；脚本文件（`Image2PDF.py`）、打包出的 exe 文件名（`image2PDF-web.exe`/`image2PDF-cli.exe`）保持不变，只是改了对外展示的项目名。

> 运行环境：Python 3.x 以上（已在 Python 3.11 / 3.12 上验证）

> Python 依赖包：Pillow（PIL）、reportlab、Flask（用于网页界面）、pytest（用于测试）

> Version：V1.3.0

> Author：liu.qi

## 特性

* 将图片批量转换为 PDF，适用于漫画、图片文档等场景。
* 自动按每张源图片的实际尺寸生成对应页面，适用于 Kindle、iPhone、iPad 等终端阅读。
* 支持单目录转换，也支持"总目录下有多个子目录，每个子目录各生成一个 PDF"的批量场景（例如一部漫画下面按卷分文件夹）。
* 支持 jpg、jpeg、png、bmp 格式（大小写不敏感）。
* 除了命令行方式，还提供一个本地网页界面：在浏览器里点选文件夹即可转换，转换完成后可以在 Gallery 里查看每本书的封面。
* 支持"双页拼图"拆分：如果图片内容其实是两页拼在一起的跨页图（常见于扫描/截图得到的漫画双页），可以开启双页模式，转换时自动沿垂直中线把每张图左右各切成一页，并按你指定的阅读方向排好页码顺序。

## 用法零：直接下载 exe（不用装 Python）

不想装 Python 环境的话，可以直接下载打包好的 exe，双击就能用：

* 网页界面版：[image2PDF-web.exe](https://github.com/xiaosagemisery/PageWeave/releases/latest/download/image2PDF-web.exe)
* 命令行版：[image2PDF-cli.exe](https://github.com/xiaosagemisery/PageWeave/releases/latest/download/image2PDF-cli.exe)

这两个链接永远指向最新一次构建（每次仓库的 `master` 分支有代码更新，GitHub Actions 会自动重新打包并替换 Release 里的文件，链接本身不变）。也可以去 [Releases 页面](https://github.com/xiaosagemisery/PageWeave/releases)手动挑一个带版本号的历史版本下载。

用法和下面"用法一/用法二"完全一样，只是不需要 `pip install`、不需要敲 `python xxx.py`，直接双击 exe 代替对应的命令：

* `image2PDF-web.exe` 对应 `python webapp.py`——双击后会自动打开浏览器，其余操作参考下面"用法二：网页界面"。转换记录（`webdata\` 文件夹，含 Gallery 索引和封面缩略图）会生成在 exe **所在的同一个目录**下，把 exe 连同这个文件夹一起拷走就能带上所有历史记录；如果 exe 放在没有写入权限的目录（比如 `C:\Program Files`）里，需要挪到一个自己有权限写入的目录（比如桌面或专门建的文件夹）再运行。
* `image2PDF-cli.exe` 对应 `python Image2PDF.py`（含 `--double-page`/`--right-first`/`--left-first`/`--split-jpeg` 这些命令行参数，用法见下面"用法一"），区别是双击运行、脚本跑完之后窗口不会立刻关掉，会停在"按回车键退出..."，方便看清楚转换结果或报错信息再关闭。

**这两个 exe 都没有做代码签名**，Windows 双击运行时大概率会被 SmartScreen 拦一下（提示"Windows 已保护你的电脑"），点"更多信息" → "仍要运行"即可继续；部分杀毒软件也可能因为"未知发布者"报个警，属于未签名程序的正常现象，不是病毒（如果不放心，可以直接读源码或本地用下面的方式自己打包）。

## 用法一：命令行（在终端里运行脚本 + 输入文件夹路径）

**第 1 步：运行脚本**

在项目根目录下打开终端，执行：

```bash
python Image2PDF.py
```

**第 2 步：根据提示输入文件夹路径**

脚本启动后会停在下面这一行等待你输入，光标会停在冒号后面：

```
请输入图片所在的文件夹路径:
```

把你要转换的文件夹的**绝对路径**粘贴或打进去，然后回车确认。例如：

```
请输入图片所在的文件夹路径: D:\漫画\龙珠
```

路径可以直接从资源管理器地址栏复制过来，两端带不带英文引号都没关系（脚本会自动去掉）。如果输入的路径不存在或者不是一个文件夹，会提示错误并直接结束：

```
[!][错误] 路径不存在或不是一个文件夹: D:\漫画\不存在的文件夹
```

**第 3 步：等待转换完成**

输入合法路径后脚本会自动开始转换，并在终端里打印每一本书的开始/结束日志，例如：

```
脚本开始执行...
[*][转换PDF] : 开始. [名称] > [第01卷]
[*][转换PDF] : 已保存. [路径] > [D:\漫画\龙珠\第01卷.pdf]
[*][转换PDF] : 结束. [名称] > [第01卷] , 耗时 1.234567 s
...
脚本执行完成...
```

转换到哪个文件夹、生成到哪里，取决于你输入的这个目录本身是什么结构，脚本会自动判断，无需再手动选择模式：

* **输入的目录顶层本身就有图片**（例如 `D:\漫画\龙珠` 文件夹下直接放着一堆图片）：会把这些图片合并成 **1 个 PDF**，保存在这个目录**的上一级**、和这个目录本身**同级**，文件名与目录同名，即生成 `D:\漫画\龙珠.pdf`（和 `D:\漫画\龙珠` 这个装图片的文件夹平级，不会混进一堆原始图片里面）。
* **输入的目录顶层没有图片，只有若干子文件夹**（例如 `D:\漫画\龙珠` 下面是 `第01卷`、`第02卷`、`第03卷` 这样按卷分的子文件夹，每个子文件夹里才是图片）：会为**每一个含图片的子文件夹各生成一个 PDF**，统一保存在你输入的这个根目录下，即生成 `D:\漫画\龙珠\第01卷.pdf`、`D:\漫画\龙珠\第02卷.pdf`、`D:\漫画\龙珠\第03卷.pdf`（PDF 不会放进子文件夹里面）。

**可选：双页拼图拆分**

如果这批图片其实每一张都是两页拼在一起的跨页图，运行脚本时可以额外带上命令行参数（这两个参数要放在 `python Image2PDF.py` 后面，不是运行后在交互提示里输入的）：

```bash
python Image2PDF.py --double-page --right-first
```

* `--double-page`：开启双页模式，转换时会把这批图片里**每一张图**都沿垂直中线左右各切成一页（这是针对本次运行的全局开关，不会自动判断某张图是不是跨页图，所有图都会被切）。
* `--right-first` 或 `--left-first`（二选一，必须和 `--double-page` 一起使用，缺一会报错退出）：告诉脚本切开之后哪一半的页码更小、应该排在前面。
  * `--right-first`：右半边页码小，排在前面（适合从右往左翻的日式漫画）。
  * `--left-first`：左半边页码小，排在前面（适合从左往右翻的西式漫画）。
* `--split-jpeg`（可选，配合 `--double-page` 使用）：双页拆分出来的临时半页文件默认存成无损 PNG，加上这个参数会改成高质量 JPEG。对手机/扫描仪拍出来的高分辨率漫画页（比如几千万像素级别的大图）这个参数能明显加快转换速度，代价是会多引入一次有损压缩（原始扫描图 → 裁剪 → 重新编码成 JPEG），高质量设置下肉眼基本看不出差别，但严格来说不再是像素级无损。不加这个参数时默认是无损 PNG，行为和没有这个选项之前完全一样。

```bash
python Image2PDF.py --double-page --right-first --split-jpeg
```

不加这些参数、直接 `python Image2PDF.py` 运行时，行为和不支持双页拆分之前完全一样。

## 用法二：网页界面

**第 1 步：启动服务**

```bash
python webapp.py
```

终端会打印类似下面的内容，说明服务已经启动：

```
[*] 拾页 PageWeave 网页界面已启动: http://127.0.0.1:5000
 * Running on http://127.0.0.1:5000
```

程序会自动帮你打开默认浏览器；如果没有自动打开，手动在浏览器里访问 `http://127.0.0.1:5000` 即可。该服务只监听本机 `127.0.0.1`，不会暴露到局域网或公网，只有本机能访问。终端窗口需要一直开着，关闭终端（或按 `Ctrl+C`）会停止服务。

**第 2 步：在页面里选择文件夹**

页面第一个面板"1. 选择文件夹"提供两种选目录的方式，任选其一：

* **点选浏览**：面板里会列出本机的盘符（如 `C:`、`D:`），点击盘符或下面列表里的 📁 文件夹名逐级进入子目录；想返回上一级就点"↑ 上一级"按钮；面板上方的面包屑（如 `D:\ / 漫画 / 龙珠`）可以直接点击跳回任意一级。
* **粘贴路径**：在最上方的输入框里粘贴一个文件夹的完整路径（例如 `D:\漫画\龙珠`），按回车或点旁边的"跳转"按钮，直接定位过去。

当前浏览到的路径会显示在"使用此目录"按钮左边。

**可选：双页拼图拆分**

在"使用此目录"按钮下方有一个"双页模式"勾选框（每张图其实是拼版的两页，转换时会自动左右对半切开）。如果这批图片其实每一张都是两页拼在一起的跨页图，勾选它——转换时会把**这次任务里的每一张图**都自动沿垂直中线左右各切成一页（对整批图片统一生效，不会自动判断哪张是跨页图）。勾选后下面会出现两个单选项，用来指定切开后哪一半页码更小、应该排在前面：

* "右边页码小"（从右往左翻，如日式漫画）
* "左边页码小"（从左往右翻，如西式漫画）

再往下、独立于"双页模式"那个折叠区域之外，还有一个"拆分优先速度"勾选框（临时半页存成高质量 JPEG 而不是无损 PNG，高分辨率扫描页会明显更快，但不再是像素级无损——仅双页模式下生效），默认不勾选（无损 PNG）且是灰色不可点击的——只有勾选了"双页模式"之后它才会变成可以勾选的状态（因为这个选项本身只在双页拆分时才有意义）。如果这批图片是手机/扫描仪拍出来的高分辨率漫画页，勾选它能明显加快转换速度，代价是引入一次额外的有损压缩，高质量设置下肉眼基本看不出差别。

不勾选"双页模式"时，行为和网页界面原本的转换逻辑完全一样。

**第 3 步：预览并开始转换**

确认路径无误后点击**"使用此目录"**，页面会先调用预览，告诉你接下来会生成什么：

* 显示"将把该目录下的图片合并生成 1 个 PDF。"——说明该目录顶层本身有图片，会生成 1 个 PDF。
* 显示"该目录顶层没有图片,将为其下 N 个含图片的子目录各生成 1 个 PDF。"——说明会为每个子目录各生成一个 PDF。

预览下方会出现**"开始转换"**按钮（primary 高亮按钮），点击后即可开始转换；这一套自动判断的规则和命令行版本完全一致。

**第 4 步：查看转换进度**

转换开始后，页面会出现一个"转换进度"面板：进度条会按已经渲染完的页数实时显示真实百分比（无论是只生成 1 个 PDF，还是漫画有多卷分别生成多个 PDF，都是同一套按页计算的真实进度，不是靠时间估出来的假进度），下方文字同时显示百分比、当前是第几本/共几本、当前文件名、当前是第几页/共几页。任务刚启动、还没有任何一页渲染完成的极短时间内（例如 more_dirs 模式先要遍历目录树找图片）会先显示一个滚动的不确定进度条，一旦收到第一条页面进度就会切换成真实百分比。如果转换失败会在这里显示错误信息。刷新页面也没关系，页面会自动重新接上正在跑的任务继续显示进度。

**第 5 步：在 Gallery 里查看结果**

转换成功的每一本书都会在页面最下方"2. 已生成的 PDF"这个 Gallery 里追加一张封面卡片——转换过程中每完成一本就会立刻显示出来，不用等全部转完。卡片上有：

* 封面缩略图（取自这本书排序后的第一张源图）；
* 书名（PDF 文件名）和页数；
* "删除"按钮：点击只会从 Gallery 里移除这条记录和封面缩略图，**不会删除已经生成在磁盘上的 PDF 文件本身**。

Gallery 里的记录会持续累积、不会互相覆盖，即使关掉终端重启服务，之前转换过的记录依然都在。如果对同一个文件夹重复转换（比如图片有更新），Gallery 里对应的那张卡片会原地刷新封面和页数，不会重复出现两张。

**可选的环境变量**（在启动 `python webapp.py` 之前设置）：

* `PORT`：修改网页服务监听的端口，默认 `5000`。
* `IMAGE2PDF_DATA_DIR`：修改 Gallery 数据（索引 `gallery.json` 和封面缩略图）的存放目录，源码方式运行默认是项目目录下的 `webdata/`（该目录已加入 `.gitignore`，不会被提交到仓库）；打包成 exe 运行时默认改成 exe 所在目录下的 `webdata/`（见上面"用法零"）。这个环境变量在两种运行方式下都优先于各自的默认值生效。

## 本地打包成 exe（开发者用，一般用户直接下载"用法零"里的现成 exe 即可）

```bash
pip install -r requirements.txt -r requirements-build.txt
pyinstaller image2PDF-web.spec
pyinstaller image2PDF-cli.spec
```

产物在 `dist/image2PDF-web.exe`、`dist/image2PDF-cli.exe`（`dist/`、`build/` 已加入 `.gitignore`，不会被提交）。仓库根目录下的 `image2PDF-web.spec`/`image2PDF-cli.spec` 是打包配置，`.github/workflows/build-exe.yml` 这个 GitHub Actions 工作流在 `windows-latest` runner 上用同一份 spec 自动构建：每次 push 到 `master`（且改动了代码）会跑一遍测试、打包、冒烟测试，通过后覆盖更新 [Releases](https://github.com/xiaosagemisery/PageWeave/releases) 里固定的 `latest` 版本；手动 push 一个 `v1.3.1` 这样的 tag 则会额外创建一个带版本号、永久保留的正式 Release。

## 文件名排序

转换过程中最痛苦的莫过于文件名错乱导致排序结果不理想。大多数情况下用数组的 `.sort` 方式即可，但对于形如 `test_01_doc_0.png`、`test_01_doc_1.png`、`test_01_doc_11.png`、`test_01_doc_2.png` 这样带数字后缀的文件名，普通字典序排序会把 `test_01_doc_2.png` 排在 `test_01_doc_11.png` 后面，不符合预期的阅读顺序。

命令行入口和网页界面目前都使用默认排序（不区分数字大小的字典序）。如果需要按数字顺序而非字典序排序，可以在代码中调用 `convert_images2PDF_one_dir` / `convert_images2PDF_more_dirs` / `convert_images2PDF_auto` 时传入 `filename_sort_fn` 回调，该回调接收图片的完整路径，返回一个可转换为整数的值，函数会按这个数值对页面排序。
